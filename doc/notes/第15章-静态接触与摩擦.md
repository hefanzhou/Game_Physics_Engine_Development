## 二、问题背景：什么是"静态接触"

### 2.1 牛顿第三定律的延伸

第14章用过牛顿三：碰撞时 A 给 B 一个冲量 $g$，B 给 A 一个冲量 $-g$。

但当物体**静止地放在地面上**：
- 重力一直在把它往下拉（$F = mg$）。
- 它并没有穿过地面 → 必然有一个**等大反向**的"反作用力"$r$ 顶住它。
- 这个 $r$ 就是 **resting force / reaction force**。

这是**力**而不是冲量：物体并没有发生速度突变。

### 2.2 反作用力 vs 冲量

| 概念 | 物理意义 | 持续时间 | 在引擎中体现 |
|------|----------|----------|-------------|
| **冲量 Impulse** | 瞬时速度突变 | 一瞬间 | 第14章碰撞解算 |
| **反作用力 Reaction Force** | 持续支撑、维持平衡 | 整个静止期间 | 本章要解决的问题 |

> 关键差异：第14章的解算系统**只能施加冲量**，没有"持续力"机制。

### 2.3 反作用力的"长程依赖"问题

如果走"严格力学"路线（计算每个接触点的反作用力），会遇到：

- 一摞箱子（书中 Figure 15.2）：底层箱子要承担**所有上层箱子重量之和**，每个接触点的反作用力依赖整摞结构。
- **不能用迭代算法逐对求解**，必须把所有接触组成一个**全局线性方程组（LCP）**。
- 这正是商业引擎（Bullet、PhysX）的"约束求解器"的核心，但实现复杂。

> 在某些情况下（数值漂移、近似刚体），这个全局方程**根本无解**。

Millington 在本章给出的方案是另一条路：**不算反作用力，把"持续支撑"伪装成"一连串很小的冲量"** —— 即 micro-collisions。

## 三、Micro-Collisions：把静态接触当成微小碰撞

### 3.1 核心思想

> "力 = 在一段时间里持续施加的冲量序列。"

每一帧：
1. 重力先让物体向下加速一点点 → 产生一个微小的"穿入速度"。
2. 碰撞检测发现物体**已经穿入地面** → 视为一次"碰撞"。
3. 用第14章的冲量解算把这个穿入速度抵消掉。
4. 物体在视觉上稳定地"贴在地面"。

```mermaid
flowchart LR
    A[帧开始] --> B[积累重力 → 物体微速向下]
    B --> C[碰撞检测：发现已穿入]
    C --> D[施加冲量抵消向下速度]
    D --> E[物体看起来静止]
    E --> A
```

**好处**：完全复用第14章的代码，无需新开"力约束"通路。

### 3.2 引出的两个问题：抖动与永不静止

**问题 A：永远在抖**
- 重力让物体加速下沉 → 冲量解算分离它 → 弹起来一点点 → 重力又拉下来 → 又分离...
- 物体永远在地面上"颤"，不会真正静下来。

**问题 B：反弹系数放大问题**
- 解算公式：$v'_s = -c \cdot v_s$（$c$ = restitution）。
- 即便 $c$ 很小，每帧都会留下少量分离速度，物体**永远在弹**。

### 3.3 解决方案 1：剔除"加速度积累的速度"

修改"期望速度变化"公式：

$$
\boxed{\Delta v = -v_{acc} - (1+c)(v_s - v_{acc})}
$$

其中 $v_{acc}$ = **上一帧由加速度（主要是重力）积累的法向速度**：

$$
v_{acc} = a_{lastFrame} \cdot \Delta t \cdot \hat{n}
$$

**直觉**：物体本来不可能真的"加速冲入地面"，那部分速度是数值积分的副产物，不应触发反弹。我们先把它"还回去"再做正常的反弹计算。

**Cyclone 实现**：每帧记录 `lastFrameAcceleration`：

```cpp
// src/body.cpp:159-160
lastFrameAcceleration = acceleration;
lastFrameAcceleration.addScaledVector(forceAccum, inverseMass);
```

### 3.4 解决方案 2：低速时降低反弹系数

当法向相对速度低于阈值时，把 restitution 强制设为 0：

```cpp
// src/contacts.cpp:148-178
const static real velocityLimit = (real)0.25f;

real thisRestitution = restitution;
if (real_abs(contactVelocity.x) < velocityLimit) {
    thisRestitution = (real)0.0f;
}
```

**经验值**：Millington 推荐 $0.1$ 左右，Cyclone 用 $0.25$。值越小越严格不弹（更稳定，但不弹的物体显得"假"），值越大越自然但越易抖。

### 3.5 Cyclone 源码：`calculateDesiredDeltaVelocity`

把上述两步组合，得到最终公式：

```cpp
// src/contacts.cpp:148-178（节选）
void Contact::calculateDesiredDeltaVelocity(real duration)
{
    const static real velocityLimit = (real)0.25f;

    // 1) 加速度造成的"伪速度"
    real velocityFromAcc = 0;
    if (body[0]->getAwake())
        velocityFromAcc += body[0]->getLastFrameAcceleration() * duration * contactNormal;
    if (body[1] && body[1]->getAwake())
        velocityFromAcc -= body[1]->getLastFrameAcceleration() * duration * contactNormal;

    // 2) 低速削减 restitution
    real thisRestitution = restitution;
    if (real_abs(contactVelocity.x) < velocityLimit)
        thisRestitution = (real)0.0f;

    // 3) 期望速度变化
    desiredDeltaVelocity =
        -contactVelocity.x
        - thisRestitution * (contactVelocity.x - velocityFromAcc);
}
```

> 这一句 `desiredDeltaVelocity` 就把 **碰撞反弹** 和 **静态接触支撑** 统一在了同一个公式里。

## 四、摩擦的物理基础

### 4.1 静摩擦 vs 动摩擦

| 类型 | 触发条件 | 方向 | 大小 |
|------|----------|------|------|
| **静摩擦 (Static)** | 物体相对静止 | 与企图施加的"切向力"反向 | $\le \mu_s \|r\|$（与外力同步增长，直到达到上限） |
| **动摩擦 (Kinetic / Dynamic)** | 物体相对滑动 | 与**滑动速度**反向 | $= \mu_k \|r\|$（恒定） |

**关键差异（书中重点）**：
- **静摩擦反向于"力"，动摩擦反向于"速度"**。
- 一旦超过静摩擦上限（$\mu_s |r|$），瞬间切换到动摩擦。
- $\mu_k < \mu_s$：物体一旦动起来反而更易滑（生活经验：推冰箱起步最累）。

### 4.2 摩擦力公式

$$
|f_{static}| \le \mu_s |r|
$$

$$
\vec{f}_{dynamic} = -\hat{v}_{planar} \cdot \mu_k |r|
$$

其中：
- $r$：法向反作用力。
- $\hat{v}_{planar}$：物体在接触切平面内的速度方向。
- 摩擦系数是**两种材料组合**的经验值，不能由单材料系数相加得到。

> 反直觉：摩擦力**与接触面积无关**！这正是为什么 cyclone 这样"不存接触面积"的引擎也能正确处理摩擦。

### 4.3 各向同性 vs 各向异性 / 滚动摩擦

- **Isotropic（各向同性）**：所有方向 $\mu$ 相同 —— 游戏引擎的默认假设。
- **Anisotropic（各向异性）**：不同方向 $\mu$ 不同 —— 例如冰刀（沿刃方向极小，垂直刃方向极大）。
- **Rolling Friction（滚动摩擦）**：高保真轮胎模型才会用，游戏引擎一般忽略。

> Cyclone 与本章实现：**只做各向同性摩擦，且把静/动摩擦合并成一个 `friction` 系数**。

## 五、把摩擦"翻译"成冲量

### 5.1 思路转换：力 → 冲量

我们的引擎是**冲量驱动**的，但摩擦公式是**力**形式。怎么对接？

利用关系：

$$
g = f \cdot \Delta t \quad,\quad \Delta v = m^{-1} g
$$

即"一段 $\Delta t$ 内施加的力 $f$" 等价于"一个冲量 $g = f \Delta t$"。

把摩擦不等式两边都乘 $\Delta t$：

$$
\boxed{|g_{tangent}| \le \mu \cdot |g_{normal}|}
$$

> **这是本章最核心的洞见**：摩擦力的不等式直接搬到冲量上仍然成立。

于是在第14章的冲量解算里多算两个分量（切向 y、z），再用上式判一下是否超过 $\mu \cdot g_x$ 即可。

### 5.2 三方向同时解算的必要性

**第14章只解算法向速度**：因为只关心 "分开"。

**本章要解算 (x, y, z) 三个方向**：
- x = 法向（贴合方向）
- y, z = 切向（沿地面的两个方向）

> ⚠️ **不能简单复制 3 次法向算法！**
> 原因：施加 y 方向冲量会让物体**绕某个轴旋转**，导致接触点 z 方向也产生速度变化 —— 三个方向**互相耦合**，必须**同时**解。

数学形式：单方向标量 $\Delta v = K \cdot g$ 升级为三维矩阵方程：

$$
\begin{bmatrix} \Delta v_x \\ \Delta v_y \\ \Delta v_z \end{bmatrix}
= \mathbf{K} \begin{bmatrix} g_x \\ g_y \\ g_z \end{bmatrix}
$$

需要：
- 构造 $\mathbf{K}$（"单位冲量 → 速度变化"矩阵）。
- 求逆 $\mathbf{K}^{-1}$（"期望速度变化 → 所需冲量"）。
- 用 $g = \mathbf{K}^{-1} \Delta v$ 一次性算出三方向冲量。

### 5.3 关键工具：反对称矩阵（Skew-Symmetric Matrix）

第14章里有一句关键代码：
```cpp
Vector3 torquePerUnitImpulse = relativeContactPosition.cross(contactNormal);
```

这是**向量叉积**。但现在 `contactNormal` 要换成"接触基矩阵"，怎么对一个矩阵叉乘？

**结论**：向量叉积 $\vec{v} \times \vec{x}$ 等价于矩阵乘法：

$$
\vec{v} \times \vec{x} = \mathbf{S}(\vec{v}) \cdot \vec{x},\quad
\mathbf{S}(\vec{v}) = \begin{bmatrix} 0 & -c & b \\ c & 0 & -a \\ -b & a & 0 \end{bmatrix}
\quad\text{其中}\ \vec{v} = (a, b, c)
$$

$\mathbf{S}(\vec{v})$ 称为 $\vec{v}$ 的**反对称（skew-symmetric）矩阵**。

**重大意义**：原来"叉积"是向量↔向量操作，没法和"矩阵乘"链式连接。改用反对称矩阵后：
$$
\vec{v} \times \vec{x} \to \mathbf{S}(\vec{v}) \cdot \vec{x}
$$
"叉积"也变成了"矩阵乘"，**整条 pipeline 就可以全是矩阵乘法**，链式连接到底，把多次叉积/张量变换合并为单个 3×3 矩阵。

**Cyclone 实现**：

```cpp
// include/cyclone/core.h（Matrix3 内）
void setSkewSymmetric(const Vector3 vector) {
    data[0] = data[4] = data[8] = 0;
    data[1] = -vector.z;  data[2] =  vector.y;
    data[3] =  vector.z;  data[5] = -vector.x;
    data[6] = -vector.y;  data[7] =  vector.x;
}
```

### 5.4 单位冲量 → 速度变化矩阵

回想第14章的标量公式：

$$
\Delta v = m^{-1} + (q_{rel} \times d) \cdot I^{-1}(q_{rel} \times d) \cdot \hat{n}
$$

升级到矩阵版本（省略推导，对照源码看）：

```cpp
// src/contacts.cpp:300+ —— calculateFrictionImpulse 节选
Matrix3 impulseToTorque;
impulseToTorque.setSkewSymmetric(relativeContactPosition[0]);

// "skew * I⁻¹ * skew" 链式：把  冲量(世界) → 速度(世界) 的影响算出来
Matrix3 deltaVelWorld = impulseToTorque;
deltaVelWorld *= inverseInertiaTensor[0];
deltaVelWorld *= impulseToTorque;
deltaVelWorld *= -1;            // 因为 x×v = -v×x

// 第二个物体（如果有）也算一份，加进来
if (body[1]) {
    impulseToTorque.setSkewSymmetric(relativeContactPosition[1]);
    Matrix3 deltaVelWorld2 = impulseToTorque;
    deltaVelWorld2 *= inverseInertiaTensor[1];
    deltaVelWorld2 *= impulseToTorque;
    deltaVelWorld2 *= -1;
    deltaVelWorld += deltaVelWorld2;
}

// 把"世界系下的角速度贡献"换成"接触系"
Matrix3 deltaVelocity = contactToWorld.transpose();
deltaVelocity *= deltaVelWorld;
deltaVelocity *= contactToWorld;

// 加入线性贡献：m⁻¹ 当成对角矩阵加在主对角线上
deltaVelocity.data[0] += inverseMass;
deltaVelocity.data[4] += inverseMass;
deltaVelocity.data[8] += inverseMass;

// 求逆 → 得到"期望速度变化 → 所需冲量"的矩阵
Matrix3 impulseMatrix = deltaVelocity.inverse();
```

| 步骤 | 含义 |
|------|------|
| `setSkewSymmetric(qRel)` | 用接触点向量构造叉积矩阵 $\mathbf{S}$ |
| `S × I⁻¹ × S × (-1)` | "冲量 → 角速度引起的接触点速度"（角分量） |
| `+ m⁻¹ \mathbf{I}_{3}$ 加在对角线 | 加上"冲量 → 直接线速度"（线分量） |
| `B^T M B`（B = contactToWorld）| 换基到接触坐标系（法向 = x，切向 = y, z） |
| `inverse()` | 反求"想要的速度变化 → 应施加的冲量" |

> **直觉**：这个 3×3 矩阵就是接触点的"动力学劲度矩阵"，它把"我想让接触点速度怎么变"翻译成"我得施加多大冲量"。

### 5.5 静摩擦 / 动摩擦的判定与裁剪

**步骤 1**：先按"完全消除全部三方向相对速度"假设算出冲量：

```cpp
Vector3 velKill(desiredDeltaVelocity, -contactVelocity.y, -contactVelocity.z);
impulseContact = impulseMatrix.transform(velKill);
```

**步骤 2**：检查切向冲量是否在静摩擦上限内：

$$
|g_{planar}| = \sqrt{g_y^2 + g_z^2} \le \mu \cdot g_x \;?
$$

```cpp
real planarImpulse = real_sqrt(impulseContact.y*impulseContact.y +
                               impulseContact.z*impulseContact.z);
if (planarImpulse > impulseContact.x * friction) {
    // 进入动摩擦分支，下面会裁剪
}
```

**步骤 3**：若超出 → 改用**动摩擦**：把切向冲量裁剪到刚好等于 $\mu \cdot g_x$（且法向 $g_x$ 也要重算，因为切向裁剪反过来会影响法向期望）：

```cpp
// 单位化切向方向
impulseContact.y /= planarImpulse;
impulseContact.z /= planarImpulse;

// 重新求出与之自洽的法向冲量大小
impulseContact.x = deltaVelocity.data[0]
                 + deltaVelocity.data[1]*friction*impulseContact.y
                 + deltaVelocity.data[2]*friction*impulseContact.z;
impulseContact.x = desiredDeltaVelocity / impulseContact.x;

// 切向 = 单位方向 × (μ × 法向)
impulseContact.y *= friction * impulseContact.x;
impulseContact.z *= friction * impulseContact.x;
```

> **静摩擦分支**：完全消除切向速度（"卡住不滑"）。
> **动摩擦分支**：切向冲量被裁剪到 $\mu \cdot g_x$，物体会留下"滑过去"的残余速度，正是我们看到的"摩擦慢慢减速"。

```cpp
// src/contacts.cpp:218-230
if (friction == (real)0.0) {
    impulseContact = calculateFrictionlessImpulse(inverseInertiaTensor);   // 走第14章简化标量算法

    impulseContact = calculateFrictionImpulse(inverseInertiaTensor);        // 走本章 3x3 矩阵算法

```

| 函数 | 适用场景 | 计算量 | 章节 |
|------|----------|--------|------|

## 七、Sequential 解算的根本局限

书末 Figure 15.6 给出一个**永远无法用顺序解算修复**的失败例子：

> 两个无穷大摩擦的箱子叠在一起，但顺序解算每次只处理一个接触：
> 处理 A 时不知道 B，处理 B 时也不知道 A。
> 几次迭代后，箱子会"滑开"，明明摩擦无穷大也阻止不了。

**根本原因**：摩擦把多个接触点**强耦合**，必须**联立求解**才正确。顺序解算无论调多少次迭代都做不到。

**真正的解决方案**：
1. 全局 LCP 联立求解（第18章 simultaneous resolution）。
2. Sleeping 机制（第16章）：让稳定的物体直接休眠，根本不参与解算。
3. 断裂物理（第17章 fracture）：高压时让结构裂开，从而避免"不可能的平衡"。

> **工程权衡**：商业引擎的稳定堆叠靠 ① + ②；游戏物理（cyclone 学习引擎）主要靠 ②，把"无法稳定"的少数情况通过让物体先休眠"绕过去"。

## 八、第15章核心收获总结

| 概念 | 第14章状态 | 第15章引入 |
|------|------------|------------|
| **静态接触** | 物体会持续"穿入"或"乱弹" | Micro-collision 把它当成微小碰撞处理 |
| **抖动 / vibration** | 永远在弹 | (1) 减去加速度伪速度 (2) 低速强制 restitution=0 |
| **摩擦** | 完全没有 | 把摩擦不等式翻译到冲量域：$\|g_{tan}\| \le \mu \|g_{nor}\|$ |
| **冲量解算维度** | 1D（仅法向） | 3D（法向 + 两切向，必须联立） |
| **核心数学工具** | $q_{rel} \times d$ 标量 | **反对称矩阵 $\mathbf{S}(\vec{v})$**：把叉积变成矩阵乘 |
| **求解结构** | $g = \Delta v / k$（标量除法） | $\vec{g} = \mathbf{K}^{-1} \Delta \vec{v}$（3×3 矩阵求逆） |
| **静/动摩擦** | — | 先按静摩擦试算 → 超出 $\mu \|g_n\|$ 上限就降级为动摩擦并裁剪 |

### 一句话总结

> **第14章解决"碰一下"，第15章用同一套冲量框架解决"放着不动"和"贴着滑"——靠 micro-collisions + 反对称矩阵 + 三方向耦合解算 + 摩擦不等式投影。**

### 仍然遗留的问题（留给第16章）

- 大量物体堆叠时性能问题（每帧大量接触都要做 3×3 求逆）。
- micro-collisions 在大堆叠下仍可能轻微抖动。
- 解决方案：**Sleeping**（休眠机制）+ **空间划分**（broad-phase 优化）+ **接触缓存**。
